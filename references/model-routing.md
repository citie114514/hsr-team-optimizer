# 模型分层与成本控制（本机实测）

数据来源：`pi --list-models`（2026-10-04 实跑）与 `~/.pi/agent/models-store.json`。
单价单位：**USD / 1M tokens**，格式 `输入 / 输出 / 缓存读`。

---

## 一、这个任务的钱花在哪

视频案例的账单：**678,350,015 tokens / $427**，3 天，约 33 次模拟迭代。

折算下来混合单价约 **$0.63 / 1M tokens**。真正的钱不在单价上，在**结构**上：

| 烧钱动作 | 为什么贵 | 本 skill 的替代方案 |
|---|---|---|
| 把战报视频反复喂给最强模型 | 每一帧都是图片 token，而且多轮对话会把历史帧反复重发 | T1 先用便宜视觉模型把帧转成「行动轴 + 分数 + 关键伤害」小表格，T3 只看表格 |
| 每轮重贴整份角色/遗器清单 | 上下文线性膨胀，第 30 轮时的输入是第 1 轮的几十倍 | 名册存文件，后续只传「变化量 + 文件名」 |
| 用最强模型做采集/整理 | 这些活不需要强推理 | 丢给免费额度池 |

**结论：先砍 token，再谈换模型。** 同一个结果，token 砍到 1/6 的效果，远大于把模型单价砍一半。

## 二、三层路由

| 层 | 职责 | 档位 | 预算占比 | 硬性要求 |
|---|---|---|---|---|
| **T1 采集** | 攻略抓取/摘要、战报帧 OCR→数值、截图识角色、名册结构化 | 免费额度池 / 最便宜的视觉模型 | ≤5% | 长上下文 + 视觉 + 中文 |
| **T2 推理** | 配队候选生成、单变量改动提议、数据比对、账本整理 | 中价 flash 级 | ~20% | 长上下文 + 工具调用稳定 |
| **T3 裁决** | 速度阈值演算、最终配队定稿、遗器目标量化、复盘规范修正 | 最强模型 | ~75%，但绝对量小 | 强推理；**只喂结构化表格** |

**铁律：原始帧 / 长视频 / 整页截图，永远不进 T3。**

## 四、推荐分配（本机）

| 阶段 | 首选 | 备选 | 理由 |
|---|---|---|---|
| P0 攻略抓取 + 摘要 | `qoder-cn GLM-5.3-Flash` | `trae Seed-2.1-Turbo` / `workbuddy cn:glm-5.3-flash` | 额度内不计费，1M 上下文，中文强 |
| 战报帧 → 数值（OCR） | `xiaomi mimo-v2.6-flash` | `workbuddy cn:glm-5.3-flash` | 有视觉，单价 0.14，输出只有数字 |
| 角色/遗器截图识别 | `xiaomi mimo-v2.6-pro` | `qoder-cn Qwen3.8-Flash` | 视觉准确度优先，调用次数少 |
| P1 名册结构化 | `workbuddy cn:deepseek-v4.1-flash` | `qoder-cn DeepSeek-Flash` | 长上下文 + 便宜 |
| P3 候选改动排序 | `zai glm-5.3-flash` | `qoder-cn GLM-5.3` | 中价档足够，thinking=medium |
| P3/T5 速度演算 + 定稿 | `zai glm-5.3`（thinking=high） | `deepseek-v4-pro` / `qoder-cn Kimi-K3` | 只喂表格，每天 <10 次调用 |
| P6 复盘规范修正 | `zai glm-5.3`（thinking=max） | `qoder-cn Qwen3.8-Max` | 一次性，值得花 |

**思考档位**：T1 用 `off`/`minimal`（省 token），T2 用 `medium`，T3 用 `high`/`max`。
本机 `settings.json` 默认 `defaultThinkingLevel: high`，做 T1/T2 时要显式降档，
否则每个采集请求都在烧思考 token。

## 五、三套预算方案（同样的 678M token 工作量）

假设输入:输出 = 8:2。

| 方案 | 配置 | 估算成本 | 说明 |
|---|---|---|---|
| **A 照搬视频** | 全部走 `zai glm-5.3`（1.4/4.4） | 678.35 × (0.8×1.4 + 0.2×4.4) = **≈ $1,357** | 比视频的 $427 还贵 3 倍。**别这么干。** |
| **B 单模型降级** | 全部走 `xiaomi mimo-v2.6-flash`（0.14/0.28） | 678.35 × 0.168 = **≈ $114** | 便宜，但强推理能力不足，配队决策质量下降 |
| **C 三层路由** | 65% 额度池 + 25% `glm-5.3-flash` + 10% `glm-5.3` | 0 + 169.6×0.2025 + 67.8×2.0 = **≈ $170** | 质量接近 A，成本 1/8 |
| **D 三层路由 + 砍 token**（**推荐**） | 同 C，但 token 降到 1/6（≈113M） | 0 + 28.3×0.2025 + 11.3×2.0 = **≈ $28** | 目标方案 |

方案 D 的 token 削减靠三件事：
1. 名册/情报/规范落盘成文件，每轮只传变化量
2. 帧由 T1 转数值，T3 永不见图
3. 账本用 `scripts/ledger.py` 维护，不靠对话历史记忆

## 六、缓存的杠杆

比换模型更有效的是**把稳定前缀做成可缓存的**：

| 模型 | 输入 | 缓存读 | 缓存折扣 |
|---|---|---|---|
| `deepseek-v4-pro` | 1.32 | 0.044 | **省 96.7%** |
| `deepseek-flash` | 0.3 | 0.006 | **省 98%** |
| `zai glm-5.3` | 1.4 | 0.26 | 省 81% |
| `zai glm-5.3-flash` | 0.15 | 0.03 | 省 80% |

**做法**：system prompt + 本期机制表 + 名册表 = 一个长期不变的前缀，放在会话最前面；
每轮只在尾部追加「本轮改动 + 实测数据」。命中缓存后，T3 的输入成本降到原来的 3%。

⚠️ 注意：`workbuddy` 网关的模型在本地 `models.json` 里没有 `cost` 字段，
按量计费未知 —— 当成「额度内免费」用，但**不要假设它有缓存折扣**。

## 七、什么时候值得用最强模型

值得：
- 速度阈值演算（「6.6 速球能不能让银狼从 183.9 到 190.5 并多打一轮」这种算得清的题）
- 两个候选改动之间的取舍（需要权衡三队整体）
- 遗器目标的量化意义（要把副词条门槛换算成分数增量）
- 复盘规范修正（把「为什么这次判断错了」抽象成规则）

不值得：
- 抄攻略
- 认截图
- 把视频逐帧描述成文字
- 复述账本里已有的数字
